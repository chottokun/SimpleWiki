# **目次型ドキュメントにおけるリンク先本文の自動先読み展開 ＆ スコアリング連携計画書**

本ドキュメントは、**SimpleWiki** の RAG（Fast / Agentic）および検索基盤において、トップページ（`index.md`）等の「目次・リンク集型ドキュメント」が選定された際に、リンク先の個別条文や解説本文を自動的に先読みしてコンテキストへ統合展開（Inlining）し、スコアリングカスタマイズと連携して回答品質を最大化するための技術設計書です。

---

## **1. 背景と課題分析**

### **1.1 現象**
法令・規程・大規模マニュアルなどのドキュメント体系では、各トピックのトップページ（`index.md`）が「条文一覧へのリンク集（目次）」となっている構造が多く存在します。

```text
鉛中毒予防規則_2/
├── index.md                  <-- タイトル「鉛中毒予防規則」だが、中身は目次リンクのみ
├── articles/
│   ├── index.md              <-- 条文一覧（目次）
│   ├── art_001_第一条（定義）.md <-- 実際の鉛中毒の定義・実態本文
│   ├── art_002_第二条（適用除外）.md
...
```

### **1.2 課題**
1. **実体本文の欠落**:
   - 検索や Fast RAG で `index.md` が最上位に選ばれた場合、渡されるコンテキストには「第1条、第2条...」という見出しリンクしか含まれず、**「鉛中毒とは何か」「具体的な規則の内容」が書かれていない**。
2. **LLM のメタ的判断による要約停止**:
   - LLM は提供された情報に忠実なため、「*提示された Wiki には目次しか記載されておらず、本文は含まれていません*」と判断し、構成の紹介だけで回答を終了してしまう。

---

## **2. 解決策：3 大アーキテクチャ設計**

### **アーキテクチャ 1: リンク先本文の自動先読み展開 (Linked Document Inlining)**

#### **【仕組み】**
コンテキストとして選定されたドキュメントが一定数以上の Markdown 相対リンク（`[見出し](./path/to/file.md)`）を含む「目次型ファイル」である場合、**そこに記載されている主要リンク先（先頭 1〜3 件、または '定義' '総則' '概要' を含むリンク）の本文を自動取得し、親コンテキストの末尾にインライン展開して LLM に渡す**。

```text
[参照Wikiコンテキスト]
---
■ 親ドキュメント: 鉛中毒予防規則 (index.md)
本文 (目次概要):
第一章 総則
第一条（定義）./articles/art_001_第一条（定義）.md
第二条（適用除外）./articles/art_002_第二条（適用除外）.md

  ▼ 【自動展開されたリンク先実体】
  ┌─ 📄 関連条文本文: 第一条（定義） (./articles/art_001_第一条（定義）.md)
  │  この省令において、鉛中毒とは、鉛、鉛合金若しくは鉛化合物を製造し...
  └────────────────────────────────────────────────────────
```

#### **【展開ルール】**
1. **親ファイル内の Markdown リンク抽出**:
   - 正規表現 `\[([^\]]+)\]\(([^)]+\.md)\)` で相対リンクを抽出。
2. **重要リンクの優先展開**:
   - リンクテキストに `定義`, `総則`, `概要`, `第1条`, `第一条`, `quickstart` を含むものを最優先で展開。
3. **文字数バジェット管理**:
   - 展開する子ドキュメントは 1 件あたり最大 800〜1,000 文字とし、全体のトークン上限（`maxDocChars`）内に収める。

---

### **アーキテクチャ 2: Agentic RAG の目次自律ドリルダウン強化**

#### **【プロンプト指示の強化】**
Agentic RAG（ReAct）において、`read_doc` で取得したファイルが目次型（リンク集）であった場合、AI が自律的にリンク先の実体を開くようシステムプロンプトを明文化します。

```text
【自律探索・目次ドリルダウンルール】
読み込んだドキュメントが目次や条文一覧（index.md や toc.md 等）であった場合は、
そこに書かれた目次だけで回答を終わらせず、記載されている相対リンク（./articles/art_...md 等）の中から、
質問のテーマに直結する条文・定義・解説ファイルを `read_doc` で必ず 1〜2 件開いて本文実体を確認してください。
```

---

### **アーキテクチャ 3: スコアリングカスタマイズとの統合設計**

目次（全体像）と個別条文（詳細・定義）のバランスを `config.json` のスコアリング設定で動的に制御できるようにします。

```json
{
  "search": {
    "rag": {
      "autoInlineLinkedDocs": true,
      "maxInlinedDocs": 2,
      "maxInlinedCharsPerDoc": 1000,
      "preferredKeywordsInLink": ["定義", "総則", "概要", "第1条", "第一条", "overview", "quickstart"]
    },
    "scoring": {
      "hybridBlend": {
        "topIndexQuota": 1,
        "detailArticleQuota": 2
      }
    }
  }
}
```

* **ハイブリッド配分の効果**:
  - Fast RAG で上位 3 件を取得する際、1 件を「トピック全体の `index.md`（全体像把握）」、残り 2 件を「本文一致度の高い個別条文（`art_...md`）」から自動選定することで、**全体構成と具体的条文の双方を完璧に満たす回答** を生成可能にします。
