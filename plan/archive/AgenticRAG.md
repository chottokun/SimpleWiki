# 2モード制 RAG アーキテクチャ詳細設計・実装計画

## 1. 2モードの明確な定義と役割分担

| 評価軸 | ⚡ Fast RAG (通常モード) | 🧠 Agentic RAG (深掘り・調査モード) |
| --- | --- | --- |
| **設計思想** | **低遅延・高応答性 (Low Latency)** | **高精度・自律網羅性 (High Autonomy)** |
| **処理モデル** | 1-Pass（検索 1回 ➔ LLM生成 1回） | ReActループ（思考 ➔ ツール実行 ➔ 再評価 ➔ 最終回答） |
| **処理時間** | **1 〜 2 秒** (即答) | **5 〜 15 秒** (じっくり調査) |
| **検索アプローチ** | 質問文そのままのキーワードでOKFスコアリング | クエリ分解、別名検索、Wiki相対リンク追跡、用語集参照 |
| **主対象ユースケース** | ・単一事実の確認（「DBのデフォルトポートは？」）<br>

<br>・特定手順の参照（「バックアップ手順は？」）<br>

<br>・用語の単独確認（「K-DATとは？」） | ・複数システムの**差異比較**（「AとBの違いは？」）<br>

<br>・障害時の**原因調査・波及影響分析**<br>

<br>・リンクを辿った**包括的コンテキストの把握** |
| **コンテキスト長** | 検索スコア上位 2 〜 3 件（軽量） | 複数ドキュメントから必要な部分のみを集約（動的構築） |

## 3. Agentic RAG の内部動作フロー（ReAct ループ）

Agentic RAG は、LLM が以下の **4 つのバックエンドツール（PowerShell関数）** を自律的に呼び出しながら探索を進めます。

### 3.1 LLMに公開する 4 つのツール定義

```text
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ Agentic Tools (PowerShell 実行可能ファンクション)                             │
 ├─────────────────────────────────────────────────────────────────────────────┤
 │ 1. search_okf(query, domain) : OKF重み付けスコアリングで関連文書を検索     │
 │ 2. lookup_glossary(term)     : 用語集 (glossary.md) から特定の社内用語を引く │
 │ 3. read_doc(relPath)         : 指定された Markdown ファイルの本文を取得      │
 │ 4. get_linked_docs(relPath)  : 文書内の相対リンク [txt](path.md) を抽出・取得│
 └─────────────────────────────────────────────────────────────────────────────┘

```

### 3.2 自律実行シーケンス

```text
[ User ]                      [ PowerShell Server ]                 [ OpenAI 互換 LLM ]
   │                                    │                                    │
   │ ──(1) Chat Request (mode:agentic) ─>│                                    │
   │                                    │ ──(2) Prompt + Tools 提案 ────────>│
   │                                    │                                    │
   │                                    │ <─(3) Tool Call: lookup_glossary ──┤
   │                                    │       ("K-DAT")                    │
   │                                    │                                    │
   │                                    │ ──(4) 用語集の該当箇所を返却 ─────>│
   │                                    │                                    │
   │                                    │ <─(5) Tool Call: search_okf ───────┤
   │                                    │       ("基幹DB 復旧")              │
   │                                    │                                    │
   │                                    │ ──(6) 検索結果 (active文書) 返却 ─>│
   │                                    │                                    │
   │                                    │ <─(7) Tool Call: get_linked_docs ──┤
   │                                    │       ("infrastructure/db.md")     │
   │                                    │                                    │
   │                                    │ ──(8) リンク先の詳細テキスト返却 ──>│
   │                                    │                                    │
   │                                    │ <─(9) 最終統合回答 (Final Answer) ─┤
   │ <─(10) HTML/JSON レスポンス返却 ───│                                    │

```

## 4. ガードレール ＆ エラーハンドリング設計

自律型エージェントで発生しがちなトラブル（無限ループ・トークン溢れ・ハルシネーション）を制御するためのガードレールです。

### ① 無限ループ防止（Max Turns 制限）

* LLM の Tool Calling ループの上限を **最大 5 ターン** に固定。
* 5 ターンに達しても完了しない場合、それまでに集めた情報だけで回答をまとめさせる（`force_final_answer`）。

### ② コンテキスト（トークン）削減処理

* `read_doc` や `get_linked_docs` で本文を読み込む際、YAML Front Matter を除く本文テキストを **最大 2,000 文字** にトリミングし、LLM のコンテキストウィンドウの枯渇と計算コスト増大を防ぐ。

### ③ OKF 鮮度ガバナンス（`deprecated` の厳格排除）

* ツール実行時（`search_okf` / `get_linked_docs`）、PowerShell 側で `status: deprecated` の文書が含まれていた場合、コンテキストに渡す前に**警告文とともに除外**、あるいは `status: active` のみを抽出して LLM へ渡す。

## 6. 実装フェーズ ＆ ロードマップ

本計画に基づく具体的な実装タスクの分解です。

```text
【Phase 1: チャットUI ＆ Fast RAG モードの確立】
  ├─ config.json に OpenAI 互換 API 設定（URL, Key, Model）を定義
  ├─ チャットUI (JavaScript/CSS) に Fast/Agentic 切替トグルを追加
  └─ Fast RAG 処理 (1回のOKF検索 ➔ プロンプト挿入 ➔ LLM回答) を実装

【Phase 2: Agentic Tools ＆ ReAct ループの実装】
  ├─ PowerShell 側で 4 つのツール関数 (search_okf, lookup_glossary 等) を作成
  ├─ Function Calling 対応の Invoke-AgenticRAG ループを実装
  └─ ターン数制限 (Max 5) とコンテキスト・トリミング処理の組み込み

【Phase 3: 思考プロセスの可視化 ＆ リンク追跡の最適化】
  ├─ ツール実行ログを thinkingLog アレイとしてクライアントへ返却
  ├─ UI 側で思考ログ（アコーディオン表示）を動的描画
  └─ OKF status: deprecated の自動除外ロジックの動作検証

```

---

この2モード計画により、**日常のちょっとした質問への「爆速回答」** と、**複雑な仕様調査や比較分析における「自律深掘り調査」** の両立が実現します。
