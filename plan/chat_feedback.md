# **AIチャット回答フィードバック（いいね / 改善要望）機能 設計計画書**

本ドキュメントは、**SimpleWiki** の AI チャット（Fast RAG / Agentic RAG）において、ユーザーが回答の品質や有用性を評価（👍 役に立った / 👎 改善が必要）できるフィードバック機能を実装し、ナレッジの継続的改善および RAG 検索精度の評価（Eval）基盤を確立するための詳細設計書です。

---

## **1. 背景と目的**

### **1.1 現状と課題**
現在、チャットログ（`logs/chat/`）および検索ログ（`logs/search/`）が詳細（verbose）に記録されるようになり、「どの質問に対して、どのドキュメントを参照し、どのような回答を生成したか」の追跡が可能になりました。
しかし、**「その回答がユーザーの疑問を本当に解決したのか」** という実利用上の定性・定量評価は、ユーザーからの直接のフィードバックがなければ把握できません。

### **1.2 導入によるメリット**
1. **RAG 精度評価（Eval）の自動データ収集**:
   - ユーザーの 👍 / 👎 判定が日次ログに蓄積されることで、「高精度な回答が生成できている分野」と「回答品質が低い（誤答・情報不足）分野」を定量的に可視化できます。
2. **Wiki ドキュメント不足の早期検知**:
   - 👎 が集中する質問クエリを抽出することで、「社内 Wiki にどの情報・手順書が不足しているか」が明確になり、ドキュメントの改善・追記計画に直結します。
3. **検索スコアリングへの将来的な好循環（RLHF 的活用）**:
   - 👍 を多く獲得した回答で参照された優良ドキュメントに対し、検索スコアの重み付けボーナス（信頼度加点）を将来的に付与可能になります。

## **2. ユーザーインターフェース設計（チャット UI）**

### **2.1 チャット回答バブルの UI 構成**
AI アシスタントからの各回答ブロックのフッターに、邪魔にならないスタイリッシュなアクションバーを設置します。

```text
┌─────────────────────────────────────────────────────────────┐
│ 🤖 アシスタント:                                            │
│ 育児休業は法律第5条に基づき、原則として子が1歳に達するまで... │
│                                                             │
│ 📚 参照ドキュメント:                                         │
│ ・育児休業、介護休業等...施行規則 (2026-08-13)               │
│                                                             │
│ ─────────────────────────────────────────────────────────── │
│ 役に立ちましたか？  [ 👍 役に立った ]  [ 👎 改善が必要 ]    │
└─────────────────────────────────────────────────────────────┘
```

### **2.2 インタラクションの流れ**
1. **初期状態**:
   - 回答生成完了後、各回答バブルの下部に `👍` と `👎` ボタンが表示されます。
2. **ワンタップ送信**:
   - `👍` または `👎` をクリックすると、ボタンがアクティブ（青色 / オレンジ色）になり、即座にサーバーへ非同期送信されます。
   - `「フィードバックありがとうございます！」` というトースト通知または控えめなメッセージが表示されます。
3. **詳細コメント（任意・オプショナル）**:
   - `👎` を押した際、小さなインライン入力欄（「どこが分かりにくかったですか？（任意）」）が展開し、追加のコメントを送信できます。
4. **二重送信防止**:
   - 同一回答に対して 1 回のみ送信可能（クリック後にボタンが無効化または選択済み状態になります）。

## **3. バックエンド API 仕様設計**

### **3.1 エンドポイント定義**
- **URI**: `POST /api/chat/feedback`
- **Content-Type**: `application/json; charset=utf-8`

### **3.2 リクエストペイロード (`JSON`)**
```json
{
  "messageId": "msg_20260815_215000_123",
  "timestamp": "2026-08-15T21:50:00.123+09:00",
  "mode": "fast",
  "rating": "positive",
  "comment": "非常に分かりやすかった",
  "userMessage": "育児休業とは？",
  "currentDocPath": "docs/guide.md",
  "sources": [
    {
      "title": "育児休業法",
      "relPath": "docs/law/ikuji.md"
    }
  ]
}
```

| フィールド | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| `messageId` | string | ○ | チャット応答時に払い出された一意のメッセージ ID |
| `rating` | string | ○ | `"positive"` (👍) または `"negative"` (👎) |
| `comment` | string | - | ユーザーからの任意コメント |
| `userMessage` | string | ○ | ユーザーの質問本文 |
| `currentDocPath` | string | - | 質問時に開いていたドキュメント |
| `sources` | array | - | 回答で参照されたドキュメントリスト |

### **3.3 レスポンス (`JSON`)**
```json
{
  "success": true,
  "message": "Feedback recorded successfully."
}
```

## **4. ログ永続化とデータ構造**

### **4.1 保存先ファイル**
- **ディレクトリ**: `logs/feedback/` (または `config.json` で指定されたフォルダ)
- **ファイル名**: `feedback_yyyy-MM-dd.jsonl`

### **4.2 記録形式（JSON Lines 1 行の例）**
```json
{
  "timestamp": "2026-08-15T21:50:05.456+09:00",
  "messageId": "msg_20260815_215000_123",
  "rating": "positive",
  "comment": "",
  "userMessage": "育児休業とは？",
  "mode": "fast",
  "model": "gpt-oss-120b",
  "currentDocPath": "docs/guide.md",
  "sources": [
    { "title": "育児休業法", "relPath": "docs/law/ikuji.md" }
  ]
}
```

## **5. 評価・分析（Eval）と活用ロードマップ**

```mermaid
flowchart TD
    A[ユーザーがAIチャットを利用] --> B[回答バブルに 👍 / 👎 ボタン表示]
    B -->|評価送信| C[POST /api/chat/feedback]
    C --> D[logs/feedback/feedback_yyyy-MM-dd.jsonl]
    
    subgraph 分析・改善ループ
        D --> E[日次/月次の評価集計]
        E --> F[👍 高評価クエリ・優良ドキュメントの特定]
        E --> G[👎 低評価クエリ・ナレッジ不足の抽出]
        G --> H[Wikiドキュメントの新規作成・改訂]
        F --> I[検索スコアリングの信頼度ボーナス反映]
    end
```

### **フェーズ別ロードマップ**
1. **フェーズ 1 (基本実装)**:
   - チャット UI への 👍 / 👎 ボタンの組み込み
   - `/api/chat/feedback` エンドポイントの実装
   - `logs/feedback/` への日次 JSONL 保存 ＆ ログローテーション
2. **フェーズ 2 (多言語 ＆ コメント拡張)**:
   - 英語/日本語の i18n 多言語対応
   - 👎 選択時の任意コメント入力ダイアログ
3. **フェーズ 3 (管理画面 `/maintenance` 連携)**:
   - メンテナンス画面での「AI 回答満足度レポート（満足率 92% など）」および「要改善質問リスト」の可視化

## **6. 検証・品質計画**

- **Pester 自動テスト**:
  - `/api/chat/feedback` のパラメータバリデーション検証
  - フィードバックログの JSON Lines 書き込み検証
  - 不正なリクエスト（messageId 不足、rating 不正）の 400 Bad Request 処理検証
- **コーディング規約遵守**:
  - スクリプトファイルの UTF-8 with BOM 保持
  - PSScriptAnalyzer による静的解析
